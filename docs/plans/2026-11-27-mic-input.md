# wakaru: 自分のマイクも文字起こしに入れる

2026-11-27。既定はOFF。設定または開始画面で明示的にONにしたときだけ、自分のマイクも文字起こし・翻訳・書き出しに加える。

## 決めたこと

- 話者ラベル（自分/相手）は付けない。言語タグ（JA/EN）だけを残す。
- タブ音声とマイクを Web Audio で1本の `MediaStreamTrack` に混ぜ、既存の ja/en `DualRecognizer` 2本にその clone を渡す。Arbiter・Paragrapher・翻訳キューは変えない。
- マイクは既定OFF。開始画面（ready）と設定シートの両方に「自分のマイクも聞き取る」を置く。初回はチェックした時点で許可ポップアップを開く。
- マイクが使えなくてもタブ音声だけでセッションを続け、バナーで知らせる。
- 音声は保存しない。文字起こしはメモリ上にあり、書き出すとファイルに残る。コピー用ログは既定で発話を伏せる。

## なぜ混合か

マイクを別トラックのまま別認識にすると、Chrome のオンデバイス認識を2音源で同時に走らせることになる。複数音源の同時セッションは、実験的な dictation バックエンドで `service-not-allowed` になる報告がある（Chromium issue 557281743）。混合なら音源は1本のままで、既存の2本（同じトラックの clone）の構成を変えずに済む。

話者ラベルを付けるには音源ごとの認識が必要になる。今回はラベルを取らないので、この制約を避ける混合を選んだ。

## 制約

- サイドパネルは Web の許可ダイアログを出せない。初回は許可専用の拡張ページを小さいポップアップで開く。許可は拡張のオリジンに残る。
- 「今回のみ」を選ぶと、許可画面を閉じた時点で失効する。許可画面では常時許可を選ぶよう案内する。
- manifest の permission 追加は不要。`audioCapture` は packaged app 用で、extensions の permissions-list にない。
- Chrome の AEC は peer connection / WebRTC の音以外を参照しない。`AudioContext.destination` で再生するタブ音声は AEC の参照にならない（Chromium issue 687574）。スピーカーでは同じ発話が直接音とマイク経由の2経路で入るため、イヤホン前提とする。
- 文字起こしは `Transcript`（メモリ）とエクスポート（ファイル）に残る。ログはコピー可能なので、発話部分を既定で伏せる。

## 実装

### 音声

`src/audio/tabAudio.ts`

- `TabAudio` に `mic: boolean` と `micError?: string` を追加。
- `TabAudioOptions` に `mic: boolean` と `onMicEnded?: () => void` を追加。
- `opts.mic || opts.noise` のとき `MediaStreamAudioDestinationNode` を作り、タブ入力を接続する。`opts.noise` なら `addNoise` を呼ぶ。
- `opts.mic` のとき `getUserMedia({ audio: { echoCancellation: true, noiseSuppression: true, autoGainControl: true } })` を取得し、ミックス先にだけ接続する（再生先には接続しない）。
- マイク取得失敗は throw せず `mic: false` と `micError` を返す。
- `ctx.resume()` 後に `ctx.state !== 'running'` ならエラー。
- セットアップ全体を try/catch し、失敗時はタブ・マイクのトラックを止め、`ctx.close()` してから rethrow。
- `stop()` で全トラックと `ctx` を閉じる。

### 設定

`src/settings.ts`

- `Settings.mic`（既定false）。
- `settingsFrom(saved)` を pure function として抽出。`saved.mic === true` のときだけ true。
- `saveSettings` に `mic` を追加。
- `tests/settings.test.ts` は `settingsFrom` だけをテストする（chrome モックなし）。

### サイドパネル

`src/sidepanel/session.ts`

- `opts.audio` に `mic` と `onMicEnded` を渡す。
- 開始ログに `mic=` を追加。
- `session.mic` / `session.micError` を公開する。

`src/sidepanel/main.ts`

- 開始画面と設定シートのチェックボックスを同期。チェックを入れた時点で、未許可なら許可ポップアップを開く。
- マイクONで開始するとき、`navigator.permissions.query({name:'microphone'})` を確認する。
  - `prompt` → 許可ポップアップを開いて ready に戻し、許可後に自動で開始する。
  - `denied` → 拡張のサイト設定を開いて ready に戻す。
  - `query` が失敗 → 続行し、取得失敗時に `micError` で拾う。
- 許可ポップアップのウィンドウは `micPermissionWindowId` で再利用する。許可後は `mic-granted` を受け取り、ポップアップが閉じてから待っていた開始を実行する。
- ポップアップが許可前に閉じられたら、待っていた開始を取り消して「もう一度「開始」を押してください」と出す。
- 許可後でも、言語変更やエンジンの再読み込みで準備が変わっていたら自動開始せず、ユーザーに「開始」を押してもらう。
- 実行中はトップバーに「マイク」バッジを出す。
- マイク失敗時はバナーを消さずに「タブ音声だけで続けます」と出す。
- ログは既定で引用符内の発話を `"…"` に伏せる。設定シートの「発話もログに表示する」で解除できる。

`src/sidepanel/index.html` / `style.css`

- 開始画面（hero）と設定シートにチェックボックスとヒント。
- 設定シートに「マイクの許可を確認」ボタン。
- トップバーに `#mic-badge`。
- ログの details に「発話もログに表示する」。

`src/sidepanel/mic-permission.html` / `micPermission.ts`

- 小さいポップアップで開く許可ページ。`getUserMedia({audio:true})` を実行し、トラックを止める。許可後はサイドパネルへ `mic-granted` を送り、画面を success 表示に変えずそのまま閉じる。
- 「今回のみ」を選んだ場合の注意は、許可ボタンの上に常時表示する（Chrome はタブが開いている間は granted を返すため、状態では区別できない）。
- 拒否時は `chrome://settings/content/siteDetails?site=chrome-extension://<id>/` を開くボタンを出す。
- `window.close()` が効かない場合に `chrome.tabs.remove` で閉じる。

`vite.config.ts`

- `micPermission: resolve(src, 'sidepanel/mic-permission.html')` を追加。

`public/manifest.json`

- `description` のみ更新。permission 追加なし。

## 検証

- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- Chrome 157 / M5 で手動:
  1. マイクOFFで開始 → 従来どおりタブ音声のみ。
  2. 開始画面でマイクON → 許可ポップアップが開く → 常時許可 → 自動で閉じる → 「開始」。
  3. 相手の音声と自分の発話の両方が字幕・翻訳に出る。
  4. イヤホンで二重なし。スピーカーでは二重（既知）。
  5. 停止で「マイク」バッジとブラウザのマイクインジケータが消える。
  6. 拡張の再読み込みと Chrome 再起動後も許可が残る。
  7. マイクをブロック → 設定リンク → 許可後に開始できる。
  8. セッション中にマイクを抜く → ログに `microphone ended`、タブ音声は継続。
  9. 書き出しに自分の発話が入る。ログは既定で伏せ字。
